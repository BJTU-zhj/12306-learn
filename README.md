# Train

Train 是一个面向火车票购票场景的 Spring Boot 多模块项目，整体参考 12306 业务流程实现。项目采用 Spring Cloud 微服务架构，包含网关、会员、车次业务、批处理、公共模块、用户端 Vue3 前台和管理端 Vue3 后台，重点实现了余票查询、乘车人管理、购票下单、订单排队、选座售票、秒杀令牌、定时生成每日车次数据等能力。

## 1. 项目架构功能

```text
train
├── train-common      # 公共模块：统一响应、异常枚举、登录上下文、拦截器、工具类
├── train-gateway     # 网关模块：统一入口、路由转发、跨域配置、JWT 配置
├── train-member      # 会员模块：会员登录、乘车人、会员车票记录
├── train-business    # 业务模块：车站车次、余票、确认订单、选座售票、秒杀令牌
├── train-batch       # 批处理模块：Quartz 定时任务、每日车次数据生成
├── generator         # 代码生成模块：MyBatis 相关代码生成
├── admin             # Vue3 管理端：基础数据、每日车次、订单、任务调度管理
├── web               # Vue3 用户端：登录、乘车人、余票查询、下单、我的车票
├── sql               # 数据库脚本
├── http              # 接口调试文件
├── jmeter            # 压测脚本
└── log               # 本地运行日志目录
```

核心模块说明：

- `train-gateway`：统一入口，默认端口 `8000`，将 `/member/**`、`/business/**`、`/batch/**` 分别转发到会员、业务、批处理服务，并统一处理跨域配置。
- `train-member`：会员服务，默认端口 `8001`，提供会员登录、乘车人维护、会员车票查询、购票成功后的车票记录保存能力。
- `train-business`：核心业务服务，默认端口 `8002`，提供车站、车次、每日车次、余票查询、验证码、秒杀令牌、确认订单、选座售票等能力。
- `train-batch`：批处理服务，默认端口 `8004`，基于 Quartz 管理定时任务，并通过 Feign 调用业务服务生成每日车次、车厢、座位和余票数据。
- `admin`：后台管理系统，基于 Vue3 + Ant Design Vue，实现基础数据维护、每日车次维护、确认订单查询、秒杀令牌管理和定时任务管理。
- `web`：用户端系统，基于 Vue3 + Ant Design Vue，实现登录、乘车人管理、余票查询、购票下单、排队状态查询和我的车票。
- `train-common`：公共基础模块，包括统一响应 `CommonResp`、分页对象、业务异常、登录上下文、拦截器、雪花 ID 工具等。

主要业务功能：

- 会员登录：支持手机号登录，并通过登录拦截器维护当前登录会员上下文。
- 乘车人管理：支持乘车人新增、修改、删除、分页查询和当前会员乘车人列表查询。
- 基础数据管理：支持车站、车次、经停站、车厢、座位等基础数据维护。
- 每日车次管理：支持每日车次、每日车站、每日车厢、每日座位和每日余票数据维护。
- 余票查询：用户端可按出发地、目的地、日期查询可售车次和不同座席余票。
- 购票下单：支持多乘车人购票、座席选择、订单初始化、异步排队处理和订单状态查询。
- 选座售票：根据座位类型、座位偏移、车厢座位 `sell` 位图计算可售座位，并更新受影响区间余票。
- 秒杀令牌：后台可维护车次令牌库存，下单前通过令牌控制进入购票链路的请求数量。
- 定时任务：后台可新增、暂停、恢复、重置、删除和手动执行 Quartz 任务。


## 2. 亮点功能技术栈

后端技术栈：

- Java 17
- Spring Boot 
- Spring Cloud 
- Spring Cloud Gateway
- Spring Cloud Alibaba Nacos
- Spring Cloud OpenFeign
- MyBatis
- MySQL
- Redis
- Redisson
- Sentinel
- Seata
- RocketMQ
- Quartz
- Kaptcha


亮点实现：

1. 登录校验与会员上下文  
   采用 `JWT + Spring Cloud Gateway 全局过滤器 + Axios 请求拦截器 + SessionStorage` 组合完成登录校验。前端登录成功后将 token 缓存在 `SessionStorage` 中，并通过 Axios 请求拦截器统一放入请求头；网关模块 `LoginMemberFilter` 统一校验 token 合法性，业务服务内部再通过 `MemberInterceptor` 解析 token 中的会员信息，并写入 `LoginMemberContext(ThreadLocal)`，从而在下单、乘车人管理、车票查询等接口中直接获取当前登录会员身份，避免业务代码反复解析请求头。  

2. MyBatis 代码生成器与 generator 模块  
   项目单独维护 `generator` 模块，通过数据库表结构统一生成 domain、mapper、xml、queryDTO 等基础代码，减少手写 CRUD 的重复工作。对于车站、车次、乘车人、每日余票、确认订单等大量基础表，生成器显著提高了开发效率，也保证了命名风格、Mapper 层结构和 XML 查询模板的一致性，便于后续扩展业务查询与分页能力。  

3. Quartz 定时任务与手动任务调度  
   在 `train-batch` 模块中集成 Quartz，通过 `SchedulerFactoryBean` 动态维护任务。后台支持新增、暂停、恢复、重置 cron、删除、立即执行等完整任务操作，既可以做每日车次数据生成、余票初始化等周期任务，也可以通过管理端手动触发执行，满足日常运维和调试场景。  

4. 基于 sell 位图的区间售票算法  
   每个座位维护一个 `sell` 字段，用二进制位图表示各个站间区间是否已售。下单时先根据出发站和到达站截取区间位，判断该区间是否存在冲突；若可售，则将对应区间位置置为 `1`，形成新的售卖状态。这个设计把“区间是否可售”的判断从复杂的多表计算，转化为字符串/位运算，大幅降低了选座和余票扣减时的判断成本，是整个购票核心算法的关键。  

5. Nacos + Gateway + Feign + 配置中心的微服务协作  
   项目基于 Nacos 实现服务注册发现和配置管理，各服务启动后注册到同一命名空间；网关模块按 `/member/**`、`/business/**`、`/batch/**` 进行统一路由转发；服务间调用通过 OpenFeign 实现，例如批处理服务调用业务服务生成每日车次数据，business 服务调用 member 服务写入会员车票记录。同时，Sentinel、Seata 等中间件配置也统一托管在 Nacos 中，降低了微服务配置分散带来的维护成本。  

6. 前端缓存、Redis 令牌缓存与分布式锁  
   前端使用 `SessionStorage` 缓存登录态、查询条件和下单中间状态，减少页面跳转后的重复请求。后端使用 Redis/Redisson 承担三类核心缓存能力：验证码缓存、秒杀令牌库存缓存、Spring Cache 查询缓存。针对高并发购票场景，又分别使用抢令牌锁和确认订单锁进行分段控制，既削峰，又保证同一车次同一日期的出票过程串行执行，降低超卖风险。  

7. RocketMQ + 前端轮询，缩短用户等待时间  
   下单接口不会同步完成全部出票流程，而是先快速完成校验、保存初始化订单、发送 RocketMQ 消息，然后立即返回订单号。消费者异步完成选座、扣减库存、写车票等后续逻辑；前端通过轮询接口查询排队状态与最终结果。这样将“用户请求耗时”与“后台重业务处理耗时”解耦，显著降低接口同步阻塞时间，改善高并发下的用户体验。  

8. Seata 分布式事务保障跨服务一致性  
   购票成功后需要同时更新 business 库中的座位售卖信息、受影响区间余票、确认订单状态，并调用 member 服务保存会员车票记录。项目在 business 侧通过 `@GlobalTransactional` 开启全局事务，将本地数据库更新与 Feign 调用 member 服务纳入同一事务链；一旦任一环节异常，Seata 负责整体回滚，避免出现“business 扣了票但 member 没生成车票记录”的跨服务数据不一致问题。  

9. 使用 JMeter 模拟抢票并进行压测  
   项目配套维护了 `jmeter` 压测脚本，通过模拟大量用户并发请求下单、查询排队结果、重复抢票等场景，对购票链路进行压力测试。压测重点验证了 Redis 令牌削峰、MQ 异步解耦、分布式锁串行处理、Sentinel 限流等机制在高并发条件下的实际效果，并用于定位锁竞争、库存扣减和消息消费中的性能瓶颈。  

10. Sentinel 限流与 Feign 熔断降级  
   在 business 模块中通过 `@SentinelResource` 对下单入口等核心资源进行保护，并接入 Sentinel Dashboard 与 Nacos 持久化规则，实现流控规则的动态管理。在 batch 模块中开启 `feign.sentinel.enabled=true`，结合 `@FeignClient(fallback = ...)` 为远程调用提供熔断降级能力，避免业务服务异常时级联拖垮调用方。  

11. 面向高并发的抢票接口整体设计  
   核心抢票链路采用“验证码校验 -> Sentinel 限流 -> Redis 令牌控制 -> 初始化订单落库 -> RocketMQ 异步排队 -> Redisson 分布式锁串行出票 -> sell 位图选座 -> Seata 分布式事务落库 -> 前端轮询结果”的组合方案。该方案通过多层削峰、异步解耦、缓存前移、锁粒度控制和事务一致性保障，将最重的出票逻辑从同步请求中剥离出来，使接口在高并发场景下仍具备可控的响应时间和较强的稳定性。
